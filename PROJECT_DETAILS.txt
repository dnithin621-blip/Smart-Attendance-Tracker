================================================================================
                    SMART ATTENDANCE TRACKER - PROJECT DETAILS
================================================================================

1. WHAT IS THE PROJECT ABOUT?
--------------------------------------------------------------------------------
This project is an automated digital attendance management system designed for 
colleges and universities. 

In traditional classrooms, teachers call out roll numbers one by one and write 
them on paper registers. This takes 5 to 10 minutes every lecture, allows students 
to give fake proxy attendance for friends, and requires teachers to manually 
calculate attendance percentages at the end of the semester.

Our project solves this by digitizing the entire process:
- Students get unique digital QR Code ID badges.
- Teachers can mark attendance either manually in one click or by scanning the 
  student's QR badge via webcam in under one second.
- The system automatically calculates attendance percentages in real-time.
- It immediately warns anyone who falls below the university minimum requirement 
  (75% attendance) to avoid exam debarment.
- Students and teachers have separate secure logins.


2. WHAT AND ALL HAS BEEN DONE? (EVERY FEATURE IMPLEMENTED)
--------------------------------------------------------------------------------
Here is the complete list of everything built and working in the project:

[A] Database Layer (Data Storage):
- Built using SQLite (`attendance.db`), containing 6 structured tables:
  1. `users`: Stores login accounts (Teacher vs Student) with encrypted passwords.
  2. `students`: Stores student roll numbers, names, emails, departments, semesters.
  3. `courses`: Stores subject codes (CS301, CS302, etc.), subject names, instructors.
  4. `attendance_sessions`: Stores each lecture conducted (date, subject, topic).
  5. `attendance_records`: Stores individual attendance status (Present, Absent, Late).
  6. `email_alerts`: Stores records of warning notifications sent to defaulters.

[B] Attendance Marking (Two Options):
1. Manual Roll Call Sheet:
   - Select subject and date to open attendance sheet.
   - Radio buttons for Present, Absent, and Late.
   - Quick buttons: "Mark All Present" and "Mark All Absent" for fast entry.
2. Live Webcam QR Code Scanner:
   - Opens laptop webcam inside the browser.
   - Scans the student's QR badge.
   - Plays an audio beep confirmation tone and records attendance instantly in SQLite.
   - Built-in 3-second cooldown prevents scanning the same person multiple times.
   - Includes fallback options: fast typing box and image file upload.

[C] Student Management (CRUD):
- Add new students with roll number, name, email, department, and semester.
- Edit existing student details.
- Delete student records.
- Instant search bar to filter students by name or roll number.

[D] Automated Student ID Badge Generator:
- Automatically creates a printable 360x480 pixel student ID card.
- Features college header banner, photo placeholder, student details, and embedded QR code.
- Downloadable as a PNG file.

[E] Attendance Percentage Engine:
- Calculates exact percentage per student overall and per individual subject.
- Formula: (Present + 0.5 * Late) / Total Sessions * 100.
- Evaluates against the 75% cutoff:
  - If >= 75%: Marked as "ELIGIBLE" (Green).
  - If < 75%: Marked as "DEFAULTER" (Red warning badge).

[F] Role-Based Login & Portals:
1. Teacher / Admin View:
   - Access to Teacher Dashboard with summary KPI cards.
   - Manual marking, webcam scanner, student directory.
   - Full reports, defaulter management, and Excel export.
2. Student View:
   - Student logs in using their roll number and password.
   - Sees their overall attendance percentage in a large colored banner.
   - Sees a breakdown table for each subject (lectures conducted, attended, percentage).
   - Can download their personal QR ID badge.

[G] Reports & Data Export:
- One-click export to styled Excel spreadsheet (`.xlsx`) with green/red status colors.
- One-click export to CSV format.

[H] Visual Analytics & Charts:
- Subject-wise average attendance bar chart.
- Attendance distribution donut chart (Excellent >=90%, Good 75-89%, Warning 60-74%, Critical <60%).
- 14-day class attendance trend line chart.

[I] Automated Shortage Alert System:
- Automatically finds all students below 75%.
- "Send Warning to All Defaulters" button generates official shortage notices.
- Built-in Mock Dispatcher logs the sent notices in database for presentation demo.
- Supports real SMTP email sending when configured.

[J] Dual Running Modes:
- Web App: Run `python app.py` -> Open in browser at `http://127.0.0.1:5000`.
- Terminal App: Run `python cli.py` -> Clean command-line menu.


3. WHAT ARE THE USES? (REAL-WORLD BENEFITS)
--------------------------------------------------------------------------------
1. For Teachers & Faculty:
   - Saves 5 to 10 minutes of valuable teaching time every single lecture.
   - Eliminates tedious end-of-semester manual math to figure out who has 75%.
   - Downloads official Excel attendance sheets in one click for the university office.

2. For Students:
   - Complete transparency: students can log in anytime from phone or laptop to check
     their current percentage per subject.
   - Prevents sudden surprise exam debarment at the end of the semester.
   - Digital QR pass on their phone means no lost paper attendance slips.

3. For College Administration:
   - Completely eliminates proxy attendance (someone shouting "present" for an absent friend).
   - Provides an accurate, tamper-resistant digital audit trail of when classes were held.
   - Automates parental and student warning letters.


4. HOW DID YOU GET THOSE THINGS AND ALL? (TECHNICAL IMPLEMENTATION)
--------------------------------------------------------------------------------
Here is exactly how each component was created and how it works under the hood:

1. How the Database Works (`database/db.py`):
   - Created using Python's built-in `sqlite3` module.
   - No external database server (like MySQL) is needed; the database lives in a 
     local file `data/attendance.db`.
   - Uses SQL foreign keys (`REFERENCES`) with `ON DELETE CASCADE` so deleting a 
     student automatically cleans up their attendance records.
   - Uses parameterized queries (`?`) to prevent SQL Injection attacks.

2. How the QR Code ID Badge is Created (`services/qr_service.py`):
   - We used the Python `qrcode` library.
   - When a student is registered, their roll number, name, and department are packed 
     into a text string.
   - The `qrcode.QRCode()` class generates a 2D black-and-white matrix image.
   - We then use Python's `Pillow` (PIL) library to create a 360x480 canvas, draw 
     the blue college header banner, write the student details using `ImageDraw`, 
     and paste the QR code in the center.

3. How the Live Webcam Scanner Works (`templates/qr_scanner.html` & `static/js/qr_scanner.js`):
   - We used the JavaScript library `html5-qrcode`.
   - It accesses the laptop camera using the browser's native `navigator.mediaDevices.getUserMedia` API.
   - It analyzes video frames in real time. As soon as a QR code appears in front of the lens, 
     it decodes the student roll number.
   - It uses the browser's Web Audio API to generate a high-pitched beep tone (980 Hz).
   - It immediately sends a background `fetch()` POST request to `/api/attendance/scan`.
   - Flask receives the roll number, looks up the student in SQLite, marks them 'Present', 
     and returns JSON back to the browser to display the student's name in the live feed.
   - A 3-second timestamp check (`Date.now() - lastScannedTime < 3000`) prevents 
     duplicate rapid scans of the same student.

4. How the User Interface & Web App Were Built (`app.py` & `templates/`):
   - We used the `Flask` micro-framework in Python to handle HTTP web requests and routes.
   - HTML pages are structured using `Jinja2` templating with a shared `base.html` 
     so navigation, styles, and footers stay consistent across all pages.
   - Frontend styling uses Bootstrap 5 and Bootstrap Icons for a modern, responsive look.
   - Security: Custom Python decorators (`@login_required` and `@teacher_required`) 
     check the session cookie to make sure students cannot access teacher-only pages.
   - Passwords are encrypted using SHA-256 (`hashlib.sha256`).

5. How the Reports & Excel Files Were Created (`services/report_service.py`):
   - We used the Python library `xlsxwriter`.
   - It constructs a real `.xlsx` workbook directly in system memory (`io.BytesIO`).
   - It styles the header row with dark blue backgrounds and bold white text.
   - It checks each student's percentage: if under 75%, it applies a soft red background 
     (`#fee2e2`) and red bold text; if eligible, it applies a green background (`#dcfce7`).
   - Flask's `send_file()` sends the generated workbook directly to the user's browser download folder.

6. How the Interactive Charts Work (`templates/analytics.html`):
   - `services/analytics_service.py` runs SQL queries to calculate subject averages, 
     tier distributions, and daily attendance percentages.
   - Flask passes these Python dictionaries into the HTML template as JSON (`|tojson`).
   - In the browser, `Chart.js` reads this data and draws interactive HTML5 canvas charts 
     (a bar chart for subjects, a donut chart for student tiers, and a line chart for 14-day trends).

7. How the Automated Shortage Warning System Works (`services/email_service.py`):
   - A function filters all students where `percentage < 75.0`.
   - For each defaulter, it formats a formal academic warning notice with their exact percentage.
   - In Mock Mode (default), it writes the letter into the SQLite `email_alerts` table 
     so it can be displayed immediately in the web app under "Alert Logs" during evaluation 
     without needing real email credentials.
   - It also contains code for Python's standard `smtplib` library to send real emails 
     via Gmail/SMTP when credentials are provided in `config.py`.
